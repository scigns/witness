# Security Contacts

**Owner:** Security Lead
**Status:** Active

## Preferred channel

**[GitHub Private Vulnerability Reporting](https://github.com/scigns/witness/security/advisories/new)**

This is preferred because it keeps the entire coordination process — report, triage, fix, advisory,
credit — in one auditable place, and it works without either party managing key exchange.

## Alternative channels

*Named security contacts and a PGP key will be published here before the first release. Until then,
private vulnerability reporting on GitHub is the only channel we can commit to monitoring.*

Saying so plainly is deliberate: publishing a contact address we do not yet monitor reliably would be
worse than publishing none, because a researcher would send a report into silence.

## Our commitments

| Stage | Commitment |
|---|---|
| Acknowledgement | **2 working days** |
| Initial assessment | 5 working days |
| Progress updates | At least every 7 days |
| Fix target | Critical 7 days · High 30 · Medium 90 · Low next release |
| Credit | In the advisory and release notes, unless you prefer anonymity |

Full policy, scope and safe harbour: [`SECURITY.md`](../../SECURITY.md).

## Not a security issue?

Use a [normal issue](https://github.com/scigns/witness/issues/new/choose) or
[Discussions](https://github.com/scigns/witness/discussions). We would rather receive a
non-vulnerability through this channel than have a real one go unreported because someone was unsure.
