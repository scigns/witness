# Witness marketing application

The independent public-site boundary for Witness. MKT-01B adds the reusable public shell, structured
navigation, responsive header, native mobile disclosure, footer and layout primitives. MKT-01C adds
the canonical metadata, robots, sitemap and structured-data foundation. MKT-02 adds the local brand,
interaction and provenance systems. It is not deployed and is not the final commercial homepage.

## Commands

- `pnpm --filter @witness/marketing dev` — local server on port 3002 by default.
- `pnpm --filter @witness/marketing lint` — marketing source lint.
- `pnpm --filter @witness/marketing typecheck` — strict TypeScript check.
- `pnpm --filter @witness/marketing test` — focused boundary and rendering tests.
- `pnpm --filter @witness/marketing test:e2e` — repository-owned Chrome smoke/responsive review.
- `pnpm --filter @witness/marketing build` — independent production build.
- `pnpm --filter @witness/marketing start` — run the production build.

## Configuration

The application requires no secrets and makes no protected API calls.

- `WITNESS_MARKETING_PORT` is optional and defaults to `3002` for local start/development.
- `WITNESS_MARKETING_SITE_URL` is optional and defaults to `http://localhost:3002`. It identifies the
  current deployment URL for environment checks; it is never used as the canonical public origin.
- `WITNESS_MARKETING_ENV` is optional and defaults to a non-production state. Use `production` only
  for the eventual canonical deployment.
- `WITNESS_MARKETING_INDEXABLE` is optional and defaults to false. Indexing is enabled only when its
  exact value is `true`, the environment is `production`, and the deployment origin is exactly
  `https://buildwithwitness.com`.
- `WITNESS_MARKETING_APP_URL` is optional and defaults to the verified production sign-in entry at
  `https://app.buildwithwitness.com/signin`.
- `WITNESS_MARKETING_DEMO_URL` is optional. Until MKT-07 provides a real request route, it defaults
  to a demonstration-request email addressed to the established `hello@buildwithwitness.com` role.

Navigation labels for unbuilt pages are retained as structured configuration but render as
non-interactive planned text. Only the home page, verified app sign-in, demo email and public source
repository are linked, so the shell exposes no intentionally broken routes.

`output: 'standalone'` and `Dockerfile` keep the application portable behind the existing Cloudflare
edge without selecting or provisioning a live Cloudflare deployment. MKT-01D documents the preview
provisioning gate, smoke checks and rollback procedure in
[`DEPLOYMENT.md`](../../docs/commercial-website/DEPLOYMENT.md).

Metadata is generated by `src/lib/metadata.ts`; `robots.ts` and `sitemap.ts` are environment-aware.
The sitemap currently lists only `/`. `/health` is an operational probe and is intentionally excluded.
`src/components/structured-data.tsx` emits only claim-safe Organization JSON-LD.
Approved logo files, when supplied, belong in `public/brand/`; the current shell intentionally keeps
the approved `witness-logo.png` artwork there. The component preserves its intrinsic dimensions and
does not apply filters or colour transforms.

## Browser review

The focused MKT-02E browser review uses the existing `playwright-core` development dependency and an
installed Chrome/Chromium executable. It starts only the marketing dev server on port 3002, tests `/`
at six widths, verifies keyboard behaviour and exercises the unlinked noindex `/brand-fixture` route.
Override the browser path with `WITNESS_MARKETING_CHROMIUM`. Failure screenshots are written outside
the repository to `/tmp/witness-marketing-e2e` (or `MKT_E2E_ARTIFACT_DIR`).

After an HTTPS preview exists, run the same suite remotely without starting a local server:

```sh
WITNESS_MARKETING_E2E_BASE_URL=https://preview.buildwithwitness.com \
  pnpm --filter @witness/marketing test:e2e
```
